# Command Escalation

## 方針

- 権限、ネットワーク、サンドボックス制約で失敗しそうなコマンドは、実行前にユーザーへ説明してから進める。
- こちらでの実行が難しい、または失敗して再実行しても通らない見込みが高い場合は、ユーザー自身に実行してもらう形へ切り替える。

## 実行前に必ず伝えること

- 実行したいコマンド
- そのコマンドが必要な理由
- 導入や実行によって何を確認・達成したいか

## ユーザー実行へ切り替える条件

- 権限不足で失敗し、ユーザー許可なしでは再実行できないとき
- ネットワークや環境制約で、こちらからの実行が通りにくいと判断できるとき
- ユーザー側で実行した方が早く、安全に進められるとき

## ユーザーへ依頼するときに伝えること

- 実行してほしいコマンド
- そのコマンドが必要な理由
- 実行後にこちらが続けて何をするか
- エラーが出た場合は、その内容を共有してほしいこと

## このルールが必要な理由

- 依存導入やネットワークアクセスは、ユーザーの許可や実行環境の都合に左右されやすい。
- 先に目的を説明しておくと、ユーザーが自分で実行するか、こちらに許可するかを判断しやすい。
- 失敗後に許可を求めるより、事前説明の方が作業の流れが安定する。

## 例

- 実行コマンド: `npm install`
- 理由: `rollup` を導入して、分割した `src/` から `dist/main.js` を生成し、ビルド成立を確認するため
